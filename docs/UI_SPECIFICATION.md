# ETS Mail UI 设计规范与防回退核查清单 (UI Specification & Checklist)

> **目标**：为 Email Transfer Station 提供精准、不可动摇的 UI 视觉与交互基线。每次完成前端修改后，**必须按照本清单逐项复核**；凡不符合本规范的，视为本轮改动未达标。

---

## 1. 顶栏与全局系统感规范 (Unified Topbar & Global Chrome)

1. **全站顶栏 100% 结构统一 (Unified Topbar Pattern)**：
   - 全站所有主要路由（首页 `/`、用户中心 `/user`、管理控制台 `/admin`）顶栏高度必须严格统一为 `60px`；
   - **左侧**：一律使用统一的 `<ProductBrand compact :context-label="..." />`（32px 渐变品牌徽标 + 产品标题 + 浅色场景副标）；
   - **右侧**：一律由 `<ProductSurfaceLinks />`（跨路由胶囊药丸跳转）与 `<AppUtilityMenu />`（紧凑设置齿轮 `[⚙]`，内含主题切换、语言切换与状态监控）组成；
   - **[严禁]** 任何页面保留旧版横排展开式菜单（如顶栏裸露的 `[亮色]`、`[中文 ▾]` 文本按钮或旧版 `n-page-header`）。

2. **全局零全屏遮罩与骨架屏规范 (Zero Fullscreen Blocking Spin & Seamless Skeletons)**：
   - **[严禁]** 使用跨视口或覆盖整个页面的黑色遮罩 `<n-spin description="loading...">`；
   - 异步加载期间，一律采用与最终组件形状高度一致的局部轻量 `<n-skeleton>`，严禁在首页或卡片区域弹出一个 50vh 的巨大未定义黑块；
   - 未登录访客打开首页时，立即呈现居中卡片，杜绝任何中间遮罩闪烁。

---

## 2. 页面布局与视觉层级 (Layout & Structure)

### A. 认证与登录界面 (Auth & Login)
1. **居中聚焦卡片 (Centered Auth Card)**：
   - 首页临时邮箱、用户登录、管理员登录三者视觉基准完全对齐：居中卡片（`width: min(100%, 460px)`，圆角 16px，`background: var(--ets-surface)`，投影 `0 20px 48px rgba(0,0,0,0.4)`）；
   - 徽标统一为顶部 48px 渐变图标卡片（用户/临时邮箱为邮件图标，管理员为盾牌徽标）；
   - 输入框一律采用沉浸式微凹底色（`background: rgba(255, 255, 255, 0.04); border: 1px solid var(--ets-border)`），获得焦点时光环高亮，严禁与卡片背景同色导致输入框隐形；
   - 提交按钮一律采用 42px 高度、700 字重的主色圆角按钮。

---

## 3. 收件流工作台 (Mail Stream Workspace)

1. **未选中邮件时 100% 全宽流 (Full-Width Stream Default)**：
   - 处于收件箱列表状态（`mode=list`）或无选中邮件时，邮件列表**占据 100% 工作区宽度**，单行高密度展示发件人（140~220px）、粗体主题、完整正文摘要与时间；
   - 严禁在未选中邮件时强行分割 70% 屏幕显示空荡荡的“选择一封邮件”黑板。
2. **双栏阅读模式 (Split Reader View)**：
   - 点击邮件进入详情后，以双栏或详情视图展示；
   - 详情面板左上角必须提供清晰的 **`[ ← 返回列表 ]`** 按钮，支持一键切回全宽收件流。

---

## 4. 邮件阅读器与暗黑模式 (Mail Reader & Dark Mode)

1. **发件人名片 (Sender Card)**：
   - 采用 Gmail 级发件人名片：彩色圆形首字母头像（38px）、粗体发件人名称、时间戳、以及带复制按钮的收件人地址。
2. **复制按钮 (Mail Copy Button)**：
   - 必须保持 18px 紧凑内嵌、透明无边框、悬浮高亮（`#60a5fa`）；
   - 样式选择器必须全局独立（`.admin-next-host .mail-copy-button`），严禁依赖深层父级类名嵌套。
3. **彻底杜绝刺眼白斑 (Zero White-Box Bleed)**：
   - 暗黑模式下，所有邮件正文容器（`.mail-body`、`.html-body`）与 iframe 背景必须硬化为深色（`#181b22` / `#161920`）；
   - 域名/状态下拉菜单必须使用纯深色定制 Popover（`#1e222b`），严禁使用原生 `<select>` 在 Windows 下弹出的白底隐形字菜单。

---

## 5. 文案与语义规范 (Copywriting & Terms)

1. **[严禁] 暴露后端实现细节与底层技术术语 (No Backend Implementation Jargon)**：
   - 严禁在任何前端可见界面（包括普通用户端、管理控制台与操作弹窗）出现后端/数据库实现细节词汇（如：`D1`、`KV`、`Worker`、`JWT`、`HS256`、`哈希`、`写入数据库`、`表结构`、`底层代理` 等）；
   - 必须统一转化为面向最终用户的自然产品功能用语：
     - `JWT` / `Token` → `登录凭证`、`访问凭证` 或 `登录链接`；
     - `写入 D1` / `D1 记录` → `保存地址`、`创建地址` 或 `系统托管记录`；
     - `Worker 读取` / `生产写入` → `加载数据`、`保存更改`；
   - 严禁出现开发调试或工程日志口吻（如：“同一套新工作台”、“暂未执行生产写入”、“只读或受限删除”）。

2. **[必须] 极简自然与去繁就简原则 (Concise & Zero-Fluff UX Writing)**：
   - 拒绝冗长繁琐的解释性长句与过度说教/恐吓式提示，提示语必须直击核心操作与结果；
   - 保持文案与系统实际能力完全一致，杜绝伪安全或自相矛盾的表述（例如：系统支持随时查看与复用的凭证，严禁提示“只显示一次 / 仅显示本次”）；
   - 确认弹窗（Confirm Modal）与操作通知文案必须简明扼要（如：“确认创建 {address}？”、“确认查看 {address} 的登录凭证？”），杜绝繁琐说教。

3. **[必须] 全量 i18n 字典覆盖 (100% i18n Coverage)**：
   - 所有面向用户的文本必须在 `message-registry.ts` 注册中英双语；
   - 严禁在界面直接渲染未翻译的 raw key（如 `admin.mailView.unread`）。

## 6. 交付前自检清单 (Pre-Delivery Checklist)

- [ ] **全站顶栏核对**：首页 `/`、用户中心 `/user`、管理端 `/admin` 顶栏结构与高度是否 100% 一致；
- [ ] **加载体验核对**：无全局黑色 `loading...` 大遮罩，骨架屏是否轻量自然；
- [ ] **登录卡片核对**：首页、用户、管理三者卡片尺寸、输入框边界与按钮是否完全对齐；
- [ ] **视觉核对**：暗黑主题下无白底方块、无原生白底下拉框；
- [ ] **布局核对**：收件列表全宽舒展无挤压；
- [ ] **文案核对**：无未翻译 key，无内部开发技术用词；
- [ ] **控件核对**：复制按钮、返回按钮各处行为和外观正常；
- [ ] **测试验证**：`corepack pnpm run test`（120 项单测 100% PASS）；
- [ ] **生产编译**：`corepack pnpm run build:pages` 零错误。
